# bc_mgmt_tool
球團管理

## 兩套工具與目前串接範圍

- `報名機器人/`：Vercel API、LINE 群組指令與網頁報名；使用既有 Firebase Admin 環境變數。
- `ranking/`：靜態 React 排點工具，使用自有 `badminton-scheduler-8a849` Firebase Google 登入與 `/rankingV1` 獨立資料區。
- 兩套工具仍可獨立使用。原本貼上名單匯入、新增球員、排點及 QR 入口保留。
- 同網站新增「報名管理／排點管理」：初次登入先建立球團與首場活動，自行填寫名稱、場地、日期時間、名額、固定名單與兩種費率；可選單次或每 1–12 週開團。報名管理可調整活動、名單、請假／恢復、開放／暫停，複製球友連結，保存與查看歷史名單，再手動確認匯入排點。

## 名單交接操作

1. 團長登入同一管理網站，在「報名管理」建立球團／活動，按「確認名單並匯入排點」。也可直接切到「排點管理」使用獨立排點。
2. 查看目前報名活動的時間、人員與固定／臨打身分。
3. 按「確認名單並預覽匯入差異」。報名端保存此次確認版本，尚未修改排點。
4. 選擇新增／移除。移除預設不勾選；手動加入的人員不自動刪除。
5. 排點已有同名者時，可明確勾選「確認為同一人並建立對應」；不自動合併、不覆寫等級、報到與繳費等人工設定。
6. 按「套用選取的變更」。新增人員未報到、不會自動上場，也不會自動標記已繳費。
7. 已連結活動的管理畫面每 30 秒檢查報名更新，顯示站內提示；不發 LINE 推播、不自動匯入。

再次匯入同一活動先顯示差異，人工調整保留。排點已有另一場活動時，團長須明確選「保存上一場，預覽新活動」，套用成功時保存舊排點至 `/rankingV1/activityArchives` 再切換，版本衝突則全部不套用。此存檔目前尚無歷史排點瀏覽介面。原有「重設」功能另有自己的保留／清除邏輯，請勿用來取代換場存檔。

## 部署前必須設定（不含秘密範例）

在報名端 Vercel 設定以下環境變數：

| 變數 | 用途 |
| --- | --- |
| `RANKING_ORIGIN` | 排點網站的 origin，例如 `https://example.github.io`，不要加路徑或尾端斜線 |
| `RANKING_AUTH_PROJECT_ID` | 排點目前 Firebase Authentication 專案 ID |
| `ROSTER_MANAGER_UIDS` | 獲准串接目前球團的團長 Firebase UID，以逗號分隔；不是 Email 或密碼 |

未設定時新 API 回傳 503 並拒絕存取；未登入或 UID 不在清單中，也不能讀取、確認報名名單。使用既有排點登入 Token，不新增共用密碼。UID 清單只授權目前既有 LINE 群組，尚不是完整多球團／Admin 模組權限後台。

排點預設連接目前程式已使用的報名 API 網址。如部署於其他網址，在 `ranking/index.html` 的設定區加入 `window.ROSTER_API_URL = 'https://your-signup.example'`。此值是網站網址，不能放 Token 或秘密。

排點端安全規則只允許獲授權團長讀寫 `/rankingV1`，其他人不能直接讀寫。`docs/ranking-rules.example.json` 提供新增規則片段：填入核准的 Firebase UID，合併到現有 `rules` 下，不要整份覆蓋原有規則。球友透過唯讀 `/api/ranking-view` 取得公開欄位，不含付款、訊息或交接識別。保留自有資料庫既有 `/badminton`、`/session` 及提供者專案，不自動遷移。新匯入使用 Firebase ETag 條件寫入：預覽後排點資料若有任何變化，停止套用並要求重新預覽。

報名資料從獨立空白 `/registrationV1` 建立：`team` 保存球團設定、`current` 保存目前活動、`archives` 保存歷史報名。原 `/session`、`absenceHistory`、既有排點資料原地保留，不讀入新後台。`eventId` 在建立活動時產生，編輯同場不換 ID；每場報名連結包含 ID，過期連結不能報到新場。LINE、網頁與團長後台共用容量與姓名檢查，使用 Firebase transaction 避免同時操作覆蓋。交接回傳只包含活動、姓名、識別碼、固定／臨打身分與費率，不包含手機、LINE 訊息或繳費狀態。確認版本保存至 `rosterHandoffs/{teamId}/{eventId}/{revision}`，`teamId` 由既有群組 ID 衍生。

## 本機驗證

### 給團長操作的虛構資料測試頁

```sh
node tests/preview/server.js
```

開啟 `http://127.0.0.1:8765/?registration`，不需要登入。完整報名模式從空白球團開始，用虛構姓名與電話測試，含建立球團、網頁報名、後台整理與匯入排點。「重新開始」只清除本機虛構資料；本機不會自動執行雲端排程。舊的差異模擬模式使用不帶參數的網址。此頁移除正式 Firebase SDK 與登入設定，以記憶體模擬名單、確認 API 及排點資料；資料連線另受 CSP 限制，不能連正式 Firebase。React／Babel／字型仍從既有公開 CDN 載入，因此需有網路。重新整理即重置虛構資料。

先按「活動匯入」完成首次匯入，再按頂端「模擬乙取消、丁報名」，再次匯入時勾選移除乙、保留新增丁；預期固定甲、臨打丁及手動丙留在排點。「模擬下一次匯入衝突」可驗證套用失敗時要求重新預覽。此預覽僅模擬交接與排點操作，不驗證真實 LINE、登入、雲端權限或帳務；QR 外部圖片在此頁被阻擋。

需要 Node.js 18 以上，無須正式憑證即可執行：

```sh
node --test tests/handoff.test.js
```

測試使用虛構資料與模擬 Firebase，涵蓋授權、名單版本、重複匯入、人工調整、上場人員保護及跨活動拒絕；不是正式環境驗收。

`tests/handoff-panel.test.js` 另驗證交接畫面的操作處理與條件寫入，需設定 `BABEL_BUNDLE` 指向提供 `babelTransform` 的 Playwright Babel 工具；未設定時明確跳過。這不是瀏覽器排版或正式 Firebase 連線測試。

排點可用靜態網站伺服器開啟 `ranking/index.html`；React／Babel／Firebase SDK 沿用原有 CDN，因此需要網路。報名 API 原本以 Vercel 部署，尚未提供離線模擬 LINE 的完整啟動環境。

## 自動開團與費用

- `cron-weekly` 保留路徑但改為每日 UTC 01:00（台灣 09:00）檢查。只有球團選固定頻率、上一場已結束、且到指定提前開放日，才保存舊名單並開下一場；單次成團不執行。排程需部署既有 `CRON_SECRET`，未設定一律拒絕。每日執行時間可能受代管排程時間窗影響，不保證準點。
- 不主動推播 LINE；僅回覆群組的報名、取消、請假／恢復、查名單指令。團長自己分享報名連結。
- 固定球友預設加入；請假後額滿不能恢復，恢復成功仍用固定費率。費率設定不代表已收款；預繳款、請假退款及正式帳務確認另行處理。
- 第一版僅核准目前群組團長；平台 Admin、新增團長與多球團權限管理尚未完成。舊 `/api/stats` 導向需登入的報名管理，移除未登入的聯絡資料輸出。

後台提供「複製球團固定連結」（每週沿用，顯示目前活動）及「複製本場活動連結」（含活動 ID，換場即失效）。正式固定入口為報名網站根網址；第一版僅對應目前授權球團，多球團固定入口需另行建立。

## Admin 與獨立球團

`PLATFORM_ADMIN_EMAILS` 設定指定的平台 Admin Email（逗號分隔），必須使用 Auth 專案簽發且 Email 已驗證的登入 Token。Admin 只增加帳號管理權限，不具有他人球團資料查看權限。既有 `ROSTER_MANAGER_UIDS` 保留首位團長的既有資料歸屬；新團長由 Admin 以 Email 加入 `accessV1/organizers`，下次以該 Google 帳號登入即生效，無須團長事先登入才能新增。

私有資料路徑由伺服器依本人 UID 決定：既有團長保留 `/registrationV1`、`/rankingV1`；其他團長及 Admin 各自使用 `/teamsV1/{UID雜湊}/registration`、`ranking`。瀏覽器不再直接讀寫私有 Firebase，而經受授權保護的 API；指定別人的 team 參數不會改變本人存取範圍。權限清單只回傳 Email 與帳號授權狀態，不回傳別人的球團資訊。

`teamSharesV1` 與 `publicTeamsV1` 保存每團獨立分享代碼。固定報名、單場連結及 QR 都要附本人分享代碼；只有透過分享連結才能取得原先允許的公開欄位，私有電話與付款狀態仍不公開。新團長不共用原 LINE 群組；LINE 群組綁定管理尚未完成，新球團先使用網頁報名。這批改動仍只在本機，尚未發布、設定正式 Admin 或新增正式存取權限。

### 本機團長權限調整

權限管理頁可各別切換報名與排點管理，移除團長須再確認，僅撤銷權限並保留球團資料。管理 API 每次驗證最新權限；畫面每 15 秒或重新切回視窗更新權限。此開關管管理端使用權限，公開球友連結維持既有流程；要停止活動報名仍使用活動的關閉報名功能。

此版未發布。未來部署新版 API 及排點前端時，必須同步套用 `docs/ranking-rules.example.json` 的私有資料區規則（由後端 Admin SDK 存取），並確認上層沒有較寬鬆的 `.read`／`.write` 授權，才能阻止舊版直接 Firebase 存取繞過撤權。既有 `/badminton`、`/session` 規則及資料不在此變更範圍；不要用片段覆蓋整份既有規則。

### 多球團／多活動本機預覽（2026-10-03）

執行 `node tests/preview/club-server.js`，預設入口 `http://127.0.0.1:8769/?registration&as=leader`。使用虛構帳號、虛構資料；狀態保存於 `/private/tmp/bc-club-preview-state.json`，不連正式 Firebase，也不送 LINE 訊息。

團長可建立自己的多個球團與活動、設定單次／每週續開、管理本場名單與預覽公告。選定活動後，按「確認名單並匯入排點」→「確認名單並預覽匯入差異」→「套用選取的變更」。再次匯入保留人工資料，移除需勾選；排點按活動獨立儲存。LINE 群組登錄、帳號綁定及跨群公告尚未實作。

新版透過 `REGISTRATION_V2=true` 與前端同名旗標啟用。實際過渡資料結構為 `clubsV2/{clubId}`（包含 defaults、events、series）、`userClubsV2/{uid}`、`eventSchedulesV2/{clubId}/{eventId}` 與 `rosterHandoffsV2/{clubId}/{eventId}`；沿用 `publicTeamsV1` 的不透明分享代碼。這是本機漸進實作，尚未遷移舊資料或發布正式環境。
