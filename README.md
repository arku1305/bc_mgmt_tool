# bc_mgmt_tool
球團管理

## 兩套工具與目前串接範圍

- `報名機器人/`：Vercel API、LINE 群組指令與網頁報名；使用既有 Firebase Admin 環境變數。
- `ranking/`：靜態 React 排點工具，使用既有 Firebase Authentication 與 Realtime Database。
- 兩套工具仍可獨立使用。原本貼上名單匯入、新增球員、排點及 QR 入口保留。
- 新增「活動匯入」：以目前報名端的活動為來源，團長確認時建立活動 ID 與名單版本，然後在排點端選擇套用差異。不是新增完整活動管理後台，也不自動開團、搬移舊資料或入帳。

## 名單交接操作

1. 團長登入排點，點選名單區的「活動匯入」。
2. 查看目前報名活動的時間、人員與固定／臨打身分。
3. 按「確認名單並預覽匯入差異」。報名端保存此次確認版本，尚未修改排點。
4. 選擇新增／移除。移除預設不勾選；手動加入的人員不自動刪除。
5. 排點已有同名者時，可明確勾選「確認為同一人並建立對應」；不自動合併、不覆寫等級、報到與繳費等人工設定。
6. 按「套用選取的變更」。新增人員未報到、不會自動上場，也不會自動標記已繳費。
7. 已連結活動的管理畫面每 30 秒檢查報名更新，顯示站內提示；不發 LINE 推播、不自動匯入。

再次匯入沿用同一活動。排點已有另一場活動時會阻擋；團長須使用既有重設流程清空當前排點再交接新活動。重設會清除既有出場紀錄，這次沒有擴充歷史排點保存，請先確認是否仍需保留。已確認的報名名單版本保存在報名資料庫，不隨排點重設刪除。

## 部署前必須設定（不含秘密範例）

在報名端 Vercel 設定以下環境變數：

| 變數 | 用途 |
| --- | --- |
| `RANKING_ORIGIN` | 排點網站的 origin，例如 `https://example.github.io`，不要加路徑或尾端斜線 |
| `RANKING_AUTH_PROJECT_ID` | 排點目前 Firebase Authentication 專案 ID |
| `ROSTER_MANAGER_UIDS` | 獲准串接目前球團的團長 Firebase UID，以逗號分隔；不是 Email 或密碼 |

未設定時新 API 回傳 503 並拒絕存取；未登入或 UID 不在清單中，也不能讀取、確認報名名單。使用既有排點登入 Token，不新增共用密碼。UID 清單只授權目前既有 LINE 群組，尚不是完整多球團／Admin 模組權限後台。

排點預設連接目前程式已使用的報名 API 網址。如部署於其他網址，在 `ranking/index.html` 的設定區加入 `window.ROSTER_API_URL = 'https://your-signup.example'`。此值是網站網址，不能放 Token 或秘密。

排點端 Realtime Database 安全規則必須允許獲授權團長讀寫 `/badminton` 及新欄位 `eventIntegration`，並實際阻擋其他人寫入。這些規則不在目前 repo，尚未驗證正式環境；不要為了讓匯入通過而開放公開寫入。新匯入使用 Firebase ETag 條件寫入：預覽後排點資料若有任何變化，停止套用並要求重新預覽。

交接回傳只包含活動、姓名、識別碼與固定／臨打身分，不包含手機、LINE 訊息或付款資料。報名端活動名單版本位於 `rosterHandoffs/{teamId}/{eventId}/{revision}`；現有 `session` 不被搬移，只增加 `rosterHandoff` 交接資料。`teamId` 由既有群組 ID 衍生，`eventId` 在團長明確確認後產生。

## 本機驗證

### 給團長操作的虛構資料測試頁

```sh
node tests/preview/server.js
```

開啟 `http://127.0.0.1:8765/`，不需要登入。此頁移除正式 Firebase SDK 與登入設定，以記憶體模擬名單、確認 API 及排點資料；資料連線另受 CSP 限制，不能連正式 Firebase。React／Babel／字型仍從既有公開 CDN 載入，因此需有網路。重新整理即重置虛構資料。

先按「活動匯入」完成首次匯入，再按頂端「模擬乙取消、丁報名」，再次匯入時勾選移除乙、保留新增丁；預期固定甲、臨打丁及手動丙留在排點。「模擬下一次匯入衝突」可驗證套用失敗時要求重新預覽。此預覽僅模擬交接與排點操作，不驗證真實 LINE、登入、雲端權限或帳務；QR 外部圖片在此頁被阻擋。

需要 Node.js 18 以上，無須正式憑證即可執行：

```sh
node --test tests/handoff.test.js
```

測試使用虛構資料與模擬 Firebase，涵蓋授權、名單版本、重複匯入、人工調整、上場人員保護及跨活動拒絕；不是正式環境驗收。

`tests/handoff-panel.test.js` 另驗證交接畫面的操作處理與條件寫入，需設定 `BABEL_BUNDLE` 指向提供 `babelTransform` 的 Playwright Babel 工具；未設定時明確跳過。這不是瀏覽器排版或正式 Firebase 連線測試。

排點可用靜態網站伺服器開啟 `ranking/index.html`；React／Babel／Firebase SDK 沿用原有 CDN，因此需要網路。報名 API 原本以 Vercel 部署，尚未提供離線模擬 LINE 的完整啟動環境。
